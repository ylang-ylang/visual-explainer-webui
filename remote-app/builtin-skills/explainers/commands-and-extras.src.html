6 Specialized References

六份专项参考：覆盖计划树、状态机验证、幻灯片、视频与扩展

参考文件 触发场景 核心输出结构与边界
references/plans.md 交互式实施计划与计划评审 左侧粘性 <ve-flow> Hero + 右侧 3 层行为主张树（<ve-claim>、<ve-code>、<ve-calls>、<ve-mock>、<ve-ask>、data-if 动态联动与 status="built" 交付回执）
references/machines.md 从代码（reducer / XState）抽状态机 <ve-flow> 内嵌 <script type="text/plain" model> 遍历 ≤ 2000 态并标出 breaks/may-break/bug-path/dead end；远程 MCP 默认关闭可执行模型（需 VISUAL_EXPLAINER_RUN_MODELS=1），远程场景改用手绘回放
references/slides.md 要求做幻灯片或 --pptx 复用 templates/slide-deck.html 引擎，每页严守 100dvh 无滚动预算（≤ 5 条要点/8 行表/10 行代码）、过 Slide delivery check，可经 visual-explainer-pptx 转 PPTX（会丢失 SVG 须补正文）
references/video.md 要求生成带旁白 MP4 或录操作教程 1280×720 虚拟时钟逐句驱动 data-say / data-beat，先出 --stills 静帧自检，再用 ElevenLabs / Seed Audio / OpenAI / xAI 合成语音，本地 ffmpeg + playwright 合成（远程 MCP 不支持）
references/themes.md 要求运行时切换配色或字体 提供 11 套固定配色（7 暗 4 亮：Dracula、Nord、One Dark、Catppuccin 等）+ 5 组字体对、右上角固定切换条契约及 visual-explainer.config.md 默认项
references/extras.md 用户提供 Mermaid、需内嵌位图或旧配方 <pre class="mermaid"> 静态转 SVG（不支持步进）；位图用脚本转 base64 禁手写；保留 v0.11 旧配方链接仅供查机制

10 Task Commands

十份任务命令：将高频工程评审与可视化场景沉淀为标准模板

命令文件 适用任务 核心骨架与关键动作
commands/generate-web-diagram.md 任意主题单页图解 提炼“读者带走的一句话”，按 SKILL.md 全规则出图并过交付核对
commands/generate-visual-plan.md 可批复的实施计划页 先查清 file:line → 写一级行为主张 → 画 Hero → 放 <ve-ask> 等答复后再写代码，完工标 status
commands/plan-review.md 对照真实代码评审计划 按 plans.md 骨架输出 Approve/Revise/Reject 结论，每个问题配 <ve-ask> 逐条采纳或拒绝
commands/diff-review.md 代码变更可视化审查 结论 + <ve-stack> 增删量 + 文件树 + 同坐标 Before/After 行为图 + 风险表 + <ve-ask> 勾选修复项
commands/compare.md 多技术方案并排对比 并排差异图 + 小多图场景 + 芯片权衡表 + 推荐理由 + <ve-ask id="pick"> 让读者拍板
commands/project-recap.md 跨周/切上下文项目回顾 一句话定位 + 架构图 + 主题时间线 + 未提交/阻塞芯片 + <ve-bars> 热点模块 + 下一步选择
commands/fact-check.md 核查已有文档与代码一致性 抽取可验证事实对照源码/git show，小改源码修正错误标签或边，顶部加验证芯片统计条
commands/state-machine.md 代码状态机全状态验错 先与用户约定 1–3 条业务不变式，再建模型遍历并给出可复现破例的最短路径脚本
commands/generate-slides.md 网页演示稿 / PPTX 按 slides.md 全量映射源纲要为多页 100dvh 幻灯片，识别 --pptx 导出标志
commands/generate-video.md 旁白 MP4 / 应用录制教程 按 video.md 核实数字后编排分镜脚本，或用 Playwright 实录 Web 应用操作流

Customization Strategy

何时保持聚合，何时新建单文件覆盖或 L2 专属子图解

保持聚合

低频且沿用官方原版

只要 16 份文档维持上游原样，统一由本页做组合哈希校验即可，保持 Admin Skills 图解树清爽不臃肿。

单文件覆盖

团队有固定审查规范

例如想给 diff-review.md 加安全检查项或给 themes.md 加公司色板，可在开启编辑后单改该文件，仅该文件偏离 upstream，其余 21 份自动跟随升级。

拆分 L2 子图解

高频定制需独立说明

当某份文档（如 references/plans.md）被深度改写后，可发布新图解设 parentId: "commands-and-extras" 且 covers 只绑定该文件，让同步状态与浏览路径精准对应。

返回 overview 查看四层总览，或进入 SKILL、kit、diagrams、motion 深入核心规范。
